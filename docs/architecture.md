# 架构与接口

本文说明 Experimental v2.2 的代码结构和可观察接口。描述以当前源码为准，
不把命名或研究灵感等同于上游项目的官方实现。

## 定位与边界

MambaIR-GPPNN 是一个独立的全色锐化研究原型。它借鉴了 MambaIR 的图像
恢复研究方向，以及 GPPNN 的模型驱动、渐进重建思路，但没有直接提供两者
的官方复现。

当前 `DualModal_ASSM` 是项目本地实现：它组合卷积、路由、门控和序列化特征
处理。仓库不依赖官方 `mamba_ssm` 运算，也没有为当前实现提供严格的复杂度
证明。因此，文档不将其称为官方 Mamba 模块，不宣称与上游数值等价，也不
给出未经分析和测量的复杂度结论。

## 输入与输出

主模型由 `models.create_mambairv2_gppnn` 创建：

```python
from models import create_mambairv2_gppnn

model = create_mambairv2_gppnn("base")
sr_1_4, sr_1_2, output = model(ms, pan)
```

输入约定：

| 名称 | 形状 | 含义 |
| --- | --- | --- |
| `ms` | `[B, 3, H, W]` | 三通道多光谱输入 |
| `pan` | `[B, 1, H, W]` | 单通道全色输入 |

输出约定：

| 名称 | 结构 | 含义 |
| --- | --- | --- |
| `sr_1_4` | `[prediction, target_from_full]` | 四分之一尺度输出组 |
| `sr_1_2` | `[prediction, target_from_full]` | 二分之一尺度输出组 |
| `output` | `[B, 3, H, W]` | 全分辨率融合结果 |

两个低分辨率输出组用于训练中的多尺度监督。输出使用 Sigmoid，范围设计为
`[0, 1]`。

## 主干数据流

1. MS 与 PAN 分别通过卷积得到浅层特征。
2. `DualModal_ASSM` 对两种模态的特征进行项目自定义的双模态处理。
3. `CrossModalAttention` 在多个阶段交换并融合模态信息。
4. 特征依次在全分辨率、二分之一分辨率和四分之一分辨率处理。
5. 低分辨率特征经转置卷积逐级解码，并与较高分辨率特征连接。
6. 模型返回四分之一、二分之一和完整分辨率输出。

主模型还包含深度可分离卷积细化、边缘门控、通道上下文和空间注意力。它们
是当前实现细节，不应在缺少消融实验时被单独解释为性能提升来源。

## Base 与 Large

工厂函数接受两个配置名称：

- `base`：`embed_dim=96`，四个双模态处理阶段。
- `large`：`embed_dim=128`，使用更宽的内部配置。

模型构造函数接受其他关键字参数，主要用于实验模块。对外使用时建议通过
工厂函数创建模型，以保持训练与加载 checkpoint 的配置一致。

当前 Large 配置在 256 输入的第一层注意力中存在通道数与六个注意力头不能
整除的兼容性风险。该配置应先做前向 smoke test，不应视为已经验证的训练
路径。

## 实验模块接口

可选参数包括：

- `use_wsm`：在第一阶段融合特征上启用状态调制。
- `use_dca_fim`：在跨模态注意力中启用实验性对齐分支。

DSC 与 WAC-X 属于训练损失，由 `train.py` 中的损失对象管理，不是主模型
输出接口的一部分。Patch Prior 是独立的推理后处理。完整限制见
[实验性世界模型组件](world-model.md)。

## 兼容性约定

- checkpoint 加载要求模型规模及实验开关与保存时一致。
- PAN 不可为 `None`。
- 当前训练与评估路径假设 MS、GT 为三通道，PAN 为单通道。
- 训练脚本面向 256 或 512 的方形输入；直接调用模型时，尺寸仍需满足多级
  下采样与解码的形状要求。
- 世界状态不是 checkpoint 公共接口的一部分；跨序列推理前应显式考虑状态
  重置和样本顺序。

## 已知限制

- 没有随仓库发布的公开权重和固定数据协议。
- 没有经独立复核的公开性能表。
- 模型名称沿用历史研究命名，不代表与 MambaIR 或 GPPNN 官方源码等价。
- 一些实验模块仅有组件测试，不能据此推断端到端收益。
- 代码当前以 RGB 三通道数据为主，不是任意波段数的通用实现。
