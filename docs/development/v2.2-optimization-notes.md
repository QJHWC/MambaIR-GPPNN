# v2.2 优化开发记录

> **历史设计记录。** 本文整理自旧版 `OPTIMIZATION_V2.2_SUMMARY.md`。
> 它记录代码演进意图，不是性能报告，不应引用其中曾出现的预期指标。

## 记录目的

v2.2 的开发重点是训练稳定性、数据一致性和实验可配置性。旧文档把若干设计
变化直接解释为性能提升；在缺少完整数据、权重和对照实验时，这种结论不能
保留。以下仅记录能够从当前代码观察到的机制。

## 当前可见变化

- 组合损失的权重和可选正则项集中在训练实现中。
- 使用 EMA 保存和验证平滑后的模型参数。
- 学习率包含预热、余弦调度与平台期处理逻辑。
- 图像读取后显式裁剪到 `[0, 1]`。
- MS、PAN、GT 的几何增强保持配对。
- 训练集额外使用轻量颜色增强。
- 训练参数支持 Base/Large、256/512、断点续训和自动批大小探测。
- 模型包含多尺度输出、边缘门控和上下文注意力。

这些机制是否改善目标任务，必须由固定协议下的消融实验回答。

## 未作为结论保留的内容

旧文档中的以下内容已撤回为未验证设想：

- 具体 PSNR/SSIM 提升；
- 固定训练时长、吞吐量与显存数字；
- “最佳”“终极”“生产级”等质量判断；
- 单个模块对性能的归因；
- 没有公开权重和原始结果支撑的对比表。

## 建议验证矩阵

1. 固定数据版本、切分与评估实现。
2. 先运行未启用实验组件的 Base 配置。
3. 每次只改变一个训练机制或模型组件。
4. 使用相同训练预算和多个随机种子。
5. 保存所有运行的命令、权重校验值和原始结果。
6. 失败或中断的运行也应记录。

## 发布检查

- README 与代码默认值一致；
- 不提交数据、checkpoint、日志或结果；
- `python train_unified.py --help` 可运行；
- Python 源码可编译；
- 组件测试通过；
- 对外结果满足 [评估指南](../evaluation.md) 的最低材料要求。

本记录不冻结未来实现；新的实测结论应写入独立实验报告，并链接可复现材料。
